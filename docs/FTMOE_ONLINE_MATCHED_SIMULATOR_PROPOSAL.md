# 保留原014模型、对齐模拟器分布：可行性与待审批方案

日期：2026-09-05。状态：方案待评审；没有修改模拟器、模型、归一化或在线实验设置。

## 可行性判断

可以恢复产生训练数据的模拟器配置和工作负载机制，这条路线允许继续使用原014的五种子v4 B_best权重，无需先做原生环境离线适配。但必须把BWGD2工作负载替换为与训练一致的OfflineTraceWorkloadV2机制，仅修改CPU/RAM/磁盘倍率不足以对齐。

需要区分三种目标：

| 目标 | 判断 | 能证明什么 |
|---|---|---|
| 在原202步输入、原种子和原配置下复现旧数据 | 工程上可行，需运行一致性验收 | 接入是否正确 |
| 新连续长输入使用相同资源映射、任务和调度机制 | 工程上可行，已有长数组候选 | 同一受控环境下的持续运行 |
| 新长流与旧训练输入的联合分布完全相同 | 不能保证 | 不能仅凭相同配置作此声明 |

推荐分两阶段实施：先恢复旧环境并通过短回放一致性检查，再评估长流是否足够匹配。该实验应称为“训练环境一致的受控模拟器实验”，不再称为协议015的原生BWGD2实验。015失败结果独立保留。

## 一、恢复配置

采用独立的 `matched_training` 模式，复用现有Simulator、RPiEdge、GOBI、Recovery无操作实现。旧入口、旧数据及归档不覆盖。

| 项目 | 拟固定值或行为 |
|---|---|
| 主机、容器上限 | 16、16 |
| 模拟间隔 | 300秒 |
| CPU容量 | CPU_CAP_SCALE=0.8，即每主机3223.2 IPS |
| RAM容量 | 前8台4295 MB，后8台8192 MB |
| 磁盘容量 | DISK_CAP_SCALE=0.25，即8053 MB |
| CPU需求 | `max(clip(source_cpu * 1.5, 0, 100) * 18.6, 2)`，任务完成后按原逻辑返回0 |
| RAM需求 | `source_ram * 1.4 * 2.0` |
| 磁盘需求 | `clip(source_disk, 0, 9) * 1000` |
| 每容器四个I/O输入 | 均为1，与训练用工作负载一致 |
| 任务总工作量 | 沿用TASK_DURATION=30及创建需求计算；实际完成时刻由执行速度决定，并非强制存活30步 |
| 初始化与补位 | 沿用dump_replay的12个初始任务及后续补位到16槽位机制 |
| 槽位身份 | 槽位绑定原输入列；迁移不更换需求来源，任务替换仍沿用该槽位输入流 |
| 调度 | 同一GOBI权重、优化过程和执行可行性检查 |
| 归一化和模型 | 保持原checkpoint统计与权重；图容量恢复训练环境对应值 |
| 标签 | 实际动作后物理过载、最大过载比资源类别；主指标继续±1步容差，延迟一间隔成熟 |

资源变换在模拟器容器需求层执行，调度、迁移可行性和标签同时使用这些需求；不能仅把喂给模型的张量乘倍率，而让模拟器继续运行另一套物理需求。

主机时序输入仍是动作前真实容器需求聚合，CPU用base IPS，不替换为Stats导出的CPU利用率；容器需求、拟调度、实际迁移分别保存。保持原dump_replay调用顺序，包括先更新trace、推进环境、任务补位、预测输入采样、调度执行与标签确认。

本路线首先保持原图输入语义和模型结构，以隔离环境变化。此前发现的图身份问题另作记录，不同时修图和换环境。若后续决定修正图语义，四组必须共同采用，并另行登记与旧模型兼容性或共同再训练方案。

## 二、连续长流来源：新增检查发现

已通过数组读取核验：

- `qos/time_series.npy` 与 `expand_old/time_series.npy` 完全相同，SHA256均为 `2b4b02d0f568081f54d69383cd56db499195adf99290fec30448d9af70716de8`，都是202×112。qos_datav0和datav0也是相同内容，不能算独立新数据。
- `version1/time_series.npy` 和 `version2/time_series.npy` 均为10002×112。按16槽位CPU/RAM/磁盘组成的整行比较，各有10002个不同的行；与旧qos仅共有初始化零行，滞后202步的整行完全相同比例为0。说明它们不是简单重复原202行，但不证明来源独立、未经人工扩增或具有独立时间演变。
- 两份长数组旁只有time_series和schedule_series，没有发现生成配置、时间戳或来源manifest。version2曾供另一套历史模型训练，不能直接称为从未使用过的数据。
- 本方案仅考虑它们的资源时序作为候选；旧schedule_series格式与本模型要求未统一，不直接复用，拟调度必须重新由本次GOBI产生。

经同一离线公式变换后的需求均值如下，均值包含各数组初始化行：

| 输入来源 | 每容器CPU均值 | RAM均值 | 磁盘均值 |
|---|---:|---:|---:|
| 原qos 202步 | 1144.28 | 680.69 | 1731.13 |
| version1 10002步 | 882.58 | 788.29 | 2003.67 |
| version2 10002步 | 890.19 | 803.14 | 2007.78 |

因此长流长度已有候选，分布完全一致仍未解决。不能因为version1均值稍接近就按模型成绩挑选它。先追溯来源、检查连续性、重复片段与历史使用范围，再按数据质量确定唯一主来源；来源不明则不进入正式确认。

若一份长数组满足来源条件，建议在去掉初始化行后，按时间顺序固定两个开发区间各1001行、三个确认区间各2001行，中间各留12行不使用，共占8053行。每条流只用前1000或2000行评分，末行确认标签；300步小试是第一开发区间的前301行。剩余数据不参与调节本次结果。

这只是待审批的划分规则，当前未切分或运行这些区间。每条流重建模拟器与模型状态，内部连续运行；不在每202步重置，不循环短数组，不跨流拼窗口。若只有一份底层长数组，报告须说明这是一个来源的不同时间段，不能将三个回放种子视为三个独立真实数据源。

### 如长来源仍不匹配

不继续搜索让D更高分的容量或压力。可报告后另选以下方向之一：

1. 更完整、可追溯的同来源连续记录，仍使用固定旧映射；这是保留原模型的优先路线。
2. 根据离线训练输入建立固定的统计映射，使新源的需求边际分布靠近旧分布。这属于新合成基准设置，必须单独审批，检查资源相关性和时间相关性，且不能称为真实原生负载。逐列分位数匹配不能保证主机聚合、调度、标签或联合分布相同。
3. 放宽“模型保持原014起点”，回到共同离线适配方案。

不建议把202步随机打乱、加噪或分块重采样后充当独立正式长流；它最多用于实现调试。

## 三、分阶段执行与停止条件

### 阶段S1：旧环境恢复与兼容性验收

1. 新建独立采集模式，使工作负载接受显式trace路径、起始行和长度，其他逻辑复用旧实现；旧默认路径与产物不动。
2. 用原开发种子31和原202步qos输入重建轨迹。检查动作前主机特征、容器需求、拟调度及原始标签与旧physical_replays/seed31一致。浮点量按明确容差比较，离散调度和标签要求一致；若不一致，先定位环境或调用顺序，不调压力补救。
3. 用模型种子1的原014指定权重，检查冻结预测与旧开发记录一致。四组初始预测必须一致。
4. 202步重建仅是工程检查，不是独立实验样本。旧块末端没有未来帧，兼容检查使用原块边界；新长流使用额外确认帧，不能将两种末端规则混淆。

### 阶段S2：长流来源与分布验收

1. 先完成长数组来源和时间结构核验，再冻结输入区间、模拟器配置及数据哈希。
2. 仅运行首条开发流的301间隔采集，暂不进行在线更新。比较旧训练数据与新流的每槽位和每主机资源分位数、零值比例、超训练范围比例、容器占用、任务替换、拟/实际迁移差异、异常比例和事件持续时间。对时间关系至少检查1、12、30步滞后相关；不能只比较全局均值。
3. 对原训练统计为0或仅有CPU底值的主机列单独检查。若长流使第14台主机再次出现病态归一化，先报告模型与场景不兼容；不通过禁止主机调度、清零负载或强行改落点隐藏问题，也不擅自改变原checkpoint归一化。
4. 冻结A评估用于发现起点失配，不用于搜索或选择模拟器参数。若初始检测仍明显偏低、数据质量不满足或关键结构差异明显，提交问题报告再讨论下一步。

### 阶段S3：原在线对比流程

通过S1/S2后，以原014五种子checkpoint进入四组300步小试，再按已批准的开发选学习率和五种子确认流程执行。A/B/C/D在线更新范围、预算、专家增删规则、标签延迟、0.65与D>B目标保持不变。每次结果使用同一条对应轨迹，检测模型不影响模拟器调度。

真实工作流的异常正常支持数门槛继续保留；不为满足门槛改标签或增加压力。动态贡献仍由D−C单独检验。所有流程遵守单进程、CPU3线程、interop1、DataLoader0、BelowNormal及既有资源保护。

## 四、审批建议

建议优先批准S1及长流来源核验，确认“旧环境能准确复现、长来源可追溯”后，再进入S2/S3。这样可先保留原014模型，避免把共同再训练引入当前问题。

该路线有望消除已查明的CPU、RAM、磁盘、I/O和任务机制失配，但不能提前承诺初始F1恢复到0.905，更不能保证普通微调长期退化、D一定胜出。更一致的环境也可能让普通微调更稳定；应如实检验。

产物拟存入独立目录，包含新协议、源数据清单、配置、短回放一致性报告、分布报告及后续逐步预测。原014归档、原015运行与分析结果保持不变。

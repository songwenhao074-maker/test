## 实验矩阵和预算

完整模型训练回放共三次，每次5968次预测；此外两次无梯度的固定路由缓存回放。

| 名称 | 内容 | 作用 |
| --- | --- | --- |
| C_ref | 原033 C_fixed5 | 同环境固定基线 |
| D_frozen_ref | 原033 D_guard_budget | 同环境原D基线 |
| D_live | 原D仅改活动专用专家/路由可训练，休眠仍冻结 | 检验持续学习 |
| D_route_fragment | D_live预测＋拆分记忆，使用固定因果路由 | 路由对照；不另训模型 |
| D_route_full | D_live预测＋完整记忆，使用同一因果路由 | 检验完整记忆能否转为在线收益 |

C_ref、D_frozen_ref、D_live用同一job、同依赖、单线程设置，独立进程顺序执行。固定底座/73维特征/初始化、每16步一次共同更新、replay64、batch32、lr1e-4、weight_decay1e-4、distill0.10、clip1、shadow预算、600+1000k新生时钟、32步复用时钟及原验收门槛均保持。当前复合损失也保持；本轮不同时测试删除蒸馏、改检测损失、延长回放或更换特征。

三次训练回放之外，不得为挑选赢家重复整条训练。允许同一逻辑run从精确checkpoint续跑，不能重抽样或重置RNG；必须记录已消费预算。缓存评分和结果序列化恢复不算新增训练。工程fixture可以使用合成输入或短段，但不得偷偷增加完整科学回放。

C_ref与D_frozen_ref分别对照033原始预测：labels/raw_labels/共享初始化精确相同，概率np.allclose(atol=2e-6,rtol=2e-6)，每个回归AP绝对差<=1e-4；D离散新生/验收/休眠/复用/拓扑事件必须一致，时间开销字段不参与比较。小浮点差在登记容差内直接通过；阈值计数差如实报告。超过容差或事件不同即保留结果、报告阻塞，不临时加大容差或自动完整重跑。

## 第一层：让活动专家继续学习

D_live仅改变训练角色：
- 四个通用专家保持原更新方式。
- 稳定活动的专用专家及其router weight/bias进入live optimizer，用同一成熟batch和原损失更新。
- 休眠专家参数、路由行和优化器状态不受其他业务更新。
- 8步crossfade期间冻结两位专用参与者，通用专家按原规则更新；完成后新活动专家恢复训练。
- 新生shadow训练/验收期间仍保持shadow与live优化器隔离。接受时保留shadow已学参数，并按登记规则转移可对应的Adam状态；明确哪些参数没有历史状态，不能静默重置其他专家的Adam moments。
- 复用时从所存专家状态恢复继续学习，保留该专家历史Adam状态。
- D_live的原生命周期控制器仍决定新生/休眠/复用。下述记忆旁路不改变其预测、更新、触发器或候选验收。

实现需检查_active_named_parameters、_apply_specialist_freeze及v2c冻结hash检查的继承链。原“所有已验收specialist都不变”检查应收窄为休眠专家和只读快照不变，同时明确只允许当前稳定活动专家变化；不能直接删除冻结不变量检查。

修改先用fixture验证活动参数确实更新、休眠参数逐字节不变、router行对应正确、旧参数Adam moments不被重建清零、crossfade规则与checkpoint恢复一致。

主对比为D_live-D_frozen_ref，同时报告D_live-C_ref。分别给出六窗均值，以及后四窗U_rec2/V_rec2/U_rec3/V_rec3均值，避免只改善初期掩盖后期退化。D_live改善原D但仍低于C，必须明确报告“第一层改善、尚未胜C”。

## 第二层：同一时刻、同一专家的完整/拆分记忆对照

在D_live中增加不参与训练决策的只读快照旁路。保留所有快照版本，不以阶段号选择或更新快照，不凭后验成绩删除差快照。每份快照必须有lineage_id、snapshot_id、创建事件、参数hash和首次可用预测索引。

固定保存时点：
1. 新生或复用后的第一次full-ramp稳定预测状态。
2. 成熟计数能被128整除，且存在稳定活动专用专家、没有crossfade时。忙时跳过，不补发。
3. 稳定活动专用专家即将被替换、crossfade开始之前。

同一lineage在同一状态hash上的重复快照去重。快照仅从创建事件之后的预测开始可用；不能补算创建前输出作为在线历史。

每个快照s产生两个配对候选：
- Full_s：保存当时四通用＋一个专用的完整残差预测器，包括所有expert权重、内部router、归一化、检测/分类头及固定ramp。底座和特征归一化可按不可变hash共享。之后独立输出完整概率，不依赖D_live后来的通用专家。
- Fragment_s(t)：取同一快照中的专用专家及其router行，与时刻t的D_live四个通用专家及其router行重组；规范化为四通用＋该专用、ramp均为1，其他活动专用与shadow不参与。

这组配对专门检验“保存一个片段”与“保存完整预测函数”的差别。Full内有多个原始MLP，须记录这是完整小型MoE记忆单元，不把它谎称为一个原始MLP专家。资源不限不等于参数量相等。

对每个时刻t，在标签可用前记录所有已存在快照的Full/Fragment检测概率和分类概率，同时记录D_live输出。两类候选使用相同输入、相同快照ID及有效行掩码；使用固定底座特征缓存时核验模型/归一化hash。Fragment的通用参数必须来自t预测前状态，不能使用流尾状态重算历史。

所有旁路推理使用独立对象/上下文、eval/no_grad；不得修改_last_z、live模式、归一化统计、RNG、优化器、controller或相似度缓存。通过有/无旁路的短段fixture比较预测、梯度更新、离散事件及状态；只排除计时字段。不要反序列化不可信来源的checkpoint，本任务只使用已核验本仓库artifact。

每个回归窗开始时，固定可比较集合：该快照在窗开始前已经存在，Full/Fragment都至少积累32个不同预测区间的成熟标签损失。窗口内部新产生的快照不得进入该窗的事后最佳集合。
输出全部配对快照的该窗AP/FPR/召回、lineage与训练来源；计算每窗配对Full-Fragment AP差的平均，再对六窗等权平均。

另计算“事后最佳固定Full快照”和“事后最佳固定Fragment快照”，分别与C_ref和D_live比较。这里使用整窗标签挑选最佳，必须标注hindsight_diagnostic=true、online_result=false。它只是现有快照库的事后单快照参照，不是任意动态路由的严格性能上界。无候选写null/原因；不得据此把少于六窗的均值包装成完整主指标。
特别检查Full最佳能否优于C、Full最佳是否优于Fragment最佳；再附同一snapshot_id的配对差，区分保存方式收益与选到了不同快照。来源处于U/V阶段不等于该快照在回归有效。

## 第三层：固定因果路由，检验可实现收益

从第二层原始预测缓存分别计算D_route_full与D_route_fragment，不再更新任何模型。两条路由使用相同快照集合和以下完全固定的算法，仅候选预测类型不同。

对每个主机h及预测时刻t：
1. 只能使用在t预测前已发布的标签，预测区间i必须满足i+2<t；这是比“同游标发布”更保守的明确顺序，不能先读取当前循环末尾才结算的标签。路由日志保存max_score_prediction_index和max_label_available_cursor。
2. 对每个候选及D_live fallback，使用相同最近32个已成熟预测区间，计算该主机的平均二元检测交叉熵。计算log前clip概率到[1e-6,1-1e-6]，原输出概率不改。候选必须在这32个区间均已产生标签前预测；不能把新快照追溯到旧数据评分。
3. 每个lineage先取近期损失最小的一个版本，再在这些版本中选最小损失候选。损失相同优先较小lineage ID，再优先较早snapshot ID；fallback在与候选打平时优先。Full和Fragment独立算损失，不能把Full选中的ID强加给Fragment。
4. 只有候选相对fallback损失改善>=1%才使用候选：L_candidate <= 0.99*L_fallback；否则使用D_live。无完整32步支持或非有限评分均fallback。每次预测重新决定，不增加未来16步验收等待，不额外调迟滞、温度或阈值。
5. 输出选中候选原有的检测和分类概率，不重校准，不用真值挑选，不读取阶段/业务/事件ID。每个主机可选择不同专家。
6. 所有选择只改变D_route_*输出；不反馈到D_live训练、记忆保存或其生命周期。这是动态记忆库的因果预测路由实验，不声称已经验证路由与梯度更新闭环共同学习。

即使第二层结果为负，也执行这两次已登记、无训练的缓存评分，保留负结果，禁止看过Full最佳后改路由算法。缓存顺序回放只有通过可用时间审计才称为因果在线模拟；事后排序不能替代这个审计。

逐次选择还要记录快照创建时间、最后训练索引，以及它是否在当前回归开始之前已经保存。将“初学时期的旧记忆”“中间W阶段快照”“本回归内部产生的新快照”的使用和表现分开作事后审计，阶段名不得参与选择。若收益主要来自本窗口新快照，不能称为恢复旧业务记忆。

第三层分别比较D_route_full-C_ref、D_route_full-D_live，以及D_route_full-D_route_fragment。若Full事后参照明显好、因果路由不领先，支持“可用记忆存在，但当前选择规则未利用”；若Full事后参照也不领先，仅增加路由复杂度缺乏依据。如果路由Full领先C但Fragment同样领先，则不能把收益全部归因于完整记忆。

## 指标、证据等级与停止条件

所有在线方法使用同一六个128步窗口：U_rec1[3300,3428)、V_rec1[3808,3936)、U_rec2[4316,4444)、V_rec2[4824,4952)、U_rec3[5332,5460)、V_rec3[5840,5968)。目标取raw[start+1:end+1]。主指标为六窗等权检测AP差，固定阈值0.5计算FPR/召回。

固定报告：六窗逐窗/均值，后四窗均值，前32/64步，各窗正负支持，W_long及五个W_gap等权AP差，全程AP/FPR，成熟/未成熟标签审计，实际路由占比、lineage与版本变化、回归时采用历史专家的延迟。AP按概率并列分组计算，不因排序顺序产生差异。

本轮开发信号门槛事先设为：对被比较基线的平均AP差>=0.005、至少4/6为正、合并正常FPR差<=0.01、W块平均AP差>=-0.02。另报告033的+0.03强参考是否达到。0.005是新的开发灵敏度，不改写033标准，不代表显著性或最优阈值。
- H1：上述门槛相对D_frozen_ref判断；另列是否胜C和后四窗是否改善。
- H2：配对保存差与事后参照分别列数值，不将事后最优套入在线成功门槛；只说明有无可利用历史能力线索。
- H3：相对C_ref判开发领先，相对D_live及Fragment路由判额外收益来源。任一对比不满足条件也保留完整结果，不只报告最好的一个。

所有方案在033结果可见后设计，只有一条开发轨迹，不作独立确认，不把16主机/六窗当作独立重复实验。D额外存储、候选与参数更多；若领先，只支持这个已披露方案在该轨迹上领先C。证明动态机制优于同容量固定专家、证明硬删除收益，属于后续另行授权实验，不在本预算中。

# 在线微调结果复核与面向 D 的下一轮场景建议

日期：2026-09-14。依据用户最新目标：寻找合理、现实可能出现、能够体现动态增删专家优势的特定情形；不要求证明 D 普遍最优，也不要求所有资源配置完全相同。

本次读取协议历史、023 原始 JSON、预测数组和训练/评估代码，独立重算已有预测，没有训练模型、生成新场景或修改历史协议结果。重算脚本：`maintenance/audit_online_results_20260914.py`；结果：`artifacts/ftmoe_online/analysis_20260914/results_audit.json`。

## 1. 最重要的判断

**当前结果没有证明 D 失败：023 的 D 根本尚未实现。当前场景主要体现固定残差的缓慢共同适应，尚未体现动态分配、保存和回收专家的明显价值。**

旧流程把“C 先学会多个机制、再明显遗忘、再出现负梯度、再需要重学”全部作为实现 D 的必要条件，过于狭窄。这是一条特定机制假说的验证流程，不是证明 D 优势的唯一途径。新协议应允许直接比较 D；梯度和遗忘用于解释结果，不再作为所有方向共同的准入条件。旧 `D_eligible=false` 保留为旧协议结果，不追改为 PASS。

合适的新目标是：**在业务模式不断加入、部分模式周期复现、可用于更新的时间有限且活动模式数随时间变化的边缘环境中，D 是否比指定固定微调基线适应更快、复现损失更小，并控制不再需要的专家开销？** 这仍需实测，不能预先保证。

## 2. 原始结果与历史概括的区别

按保存的预测数组，复现原阶段评估的有效标签掩码与 AP 定义，得到末 100 区间检测 AP：

| 阶段 | 冻结 A | 固定 C | C−A |
|---|---:|---:|---:|
| 首次 compute | 0.4062 | 0.4111 | +0.0049 |
| 首次 memory | 0.5663 | 0.5683 | +0.0020 |
| 首次 io | 0.5743 | 0.5946 | +0.0203 |
| 再现 compute | 0.4277 | 0.4848 | +0.0571 |
| 再现 io | 0.5240 | 0.6537 | +0.1297 |
| 再现 memory | 0.3977 | 0.4949 | +0.0972 |

这些是 AP 的绝对差值；乘 100 才是百分点。旧 STOP-NO-LEARN 的首次接触门槛确实未过，但不能将其扩大为“整个在线阶段 C 几乎不学习”。后半程明显改善，尚不能区分累计优化、共同迁移与机制再现各自的贡献。

固定探针也支持这个限定：终点相对起点分别提高约 0.1753、0.1295、0.1634。初期存在 0.0073、0.0150 的下降，未达注册的 0.03 门槛；“完全没有遗忘”比证据更强，准确说法是“未测得达门槛的遗忘”。从 F1 以后探针共同改善，不能据此声称已形成互相独立的专家知识。

协议 022 的 100→1600 次更新对应 AP 0.4256→0.6891，最后一次翻倍仍有收益。这些旧数值来自保留的协议文档，本次没有旧预测可独立重算；它们提示预算/优化仍值得诊断，却不足以证明当前在线失败的原因已被确定。

## 3. 本次查出的评估问题

### 3.1 阶段 onset 指标把相邻主机当成相邻时间

`run_ftmoe_protocol023_s4.py:phase_metrics()` 先把 `[时间,16主机]` 展平，再传给 `onset_metrics()` 做一位移位。因此大多数“未来”其实是同一时刻的下一台主机；最后一台才跨到下一时刻，而且主机也变了。`onset_metrics()` 的尾部有效性语句也没有真正去除缺乏未来标签的尾部。

本次独立重算沿时间轴的同主机 h=1 转变，排除阶段末尾未知未来，并区分 raw 与 tolerance 标签；阶段旧 onset 值全部可以按错误的展平算法复现。以下为 **raw 标签、整个阶段** 的正确时间轴读数：

| 阶段 | A onset AP | C onset AP |
|---|---:|---:|
| 首次 compute | 0.05037 | 0.05076 |
| 首次 memory | 0.10967 | 0.10940 |
| 首次 io | 0.17722 | 0.17710 |
| 再现 compute | 0.06774 | 0.06931 |
| 再现 io | 0.15208 | 0.14884 |
| 再现 memory | 0.09679 | 0.09082 |

修正后仍未看到稳定的预警改善。这里测的是任何资源的 host onset，不能直接等同于 H2 的资源专属、任务队列限定的 onset。该缺陷不推翻上表已经复算一致的检测 AP，也不能据此宣布其他历史 onset 实现都错了。

### 3.2 末尾有一个区间未结算，现有完整性门禁没有覆盖

两臂预测数组的第 2878 区间（从零编号）16 个 tolerance 标签全为 −1；末区间 2879 已结算。`finish()` 只补最后一行，漏了倒数第二行。旧阶段指标过滤 −1，因此原数值可复现，但 B2 少评估了 16 个 host-step。修复时应从已观测原始标签补结算，并检查所有 scored 行均已结算，而非只查最后一行。本次仅记录，没有改写旧数组。

### 3.3 诊断宏 F1 的定义也需明确

`resource_macro_f1()` 对所有输入强制给出 CPU/RAM/Disk 之一，正常样本也会计入资源分类 FP。它既不是仅在真实异常上的资源分类 F1，也不是带正常拒绝选项的端到端诊断 F1。建议分别报告真实异常上的资源宏 F1，及结合检测阈值的端到端诊断指标；全正常阶段报告 FPR，不用三资源 F1 评价。

### 3.4 专业化探针和最终任务并非同一问题

H2 用 49 维手工时间特征预测资源专属 onset；C 用冻结 v4 的 64 维表征做残差修正，训练目标是 tolerance 检测/分类加排序、蒸馏与锚点保护。H2 通过不能证明 C 的表征保存了相同信息，更不能证明动态专家能够利用它。

H2 的 within/cross AP 还跨不同测试群体，且 AP 受正例率影响。应补“同一测试群体上，不同训练来源模型的比较”，包括 pooled 固定模型；跨域差异不能直接称为顺序训练遗忘。

### 3.5 梯度结果的含义应收窄

成熟 checkpoint 的均值余弦约 +0.71～+0.95，负比例约 2.0%～9.4%，没有达到原冲突门槛。这是有效的局部诊断。探针已排除 anchor/distillation，不能未经测量把正余弦归咎于共同正则项。

但探针默认抽故障 host-step；这些样本共同要求提高异常得分，不能代表正常负例、相似前兆但不同结局等所有决策边界。64 个抽样 host-step 不必然是 64 次独立事故，4096 个交叉组合也不是独立样本量。“梯度非负”不能推出“任何形式的 D 都没有价值”。

## 4. 为什么现有设置难以突出 D

1. **机制顺序不同，不等于预测映射相互冲突。** 三种级联最终都在教模型识别资源压力；当前结果更像可共享的修正。单纯继续调 CPU/RAM/Disk 幅度和排列，成功机会有限。
2. **短驻留从首次接触就开始，可能让 D 同样来不及学会。** 每个首遇阶段只有 105 次更新，lr=1e-4，另有 0.25 anchor、0.10 distillation。新专家也有冷启动成本，不能假定新增就能立刻获益。
3. **固定 C 本身已有四个专家与可训练 router。** 三种机制并不自动构成容量不足；软路由、共用表征和优化方式都可能比专家个数更关键。
4. **“部署预算”缺乏与服务期限的定量联系。** 实测整臂 67.5 秒、720 次更新共 41.0 秒、平均一次更新 0.057 秒，只说明本机可执行；尚未建立对应的边缘设备 CPU 份额、采样周期、p95 时延与电量约束，不能称每四步更新一次是已验证的物理极限。
5. **没有专门验证删除的阶段。** 只有三模式轮换，长期保存它们可能就是最优策略；删除反而损害再现性能。
6. **资源优势很可能很小。** 可训练残差仅 9752 参数，FP32 参数裸存储约 38 KiB（未计优化器、激活和备份）。不能仅靠几个小专家就宣称解决了严重内存不足。需测真实总开销；若差异很小，优先研究适应性能。

## 5. 建议主场景：业务模式进入/退出、先充分学习、后短周期复现

这是设计建议，尚未运行，也不是已采集的工业事实。现实依据是部署中确实存在按 CPU/内存指标伸缩业务及配置资源限制的机制，见 [Kubernetes HPA 官方文档](https://kubernetes.io/docs/concepts/workloads/autoscaling/horizontal-pod-autoscale/) 和 [资源管理文档](https://kubernetes.io/docs/concepts/configuration/manage-resources-containers/)。据此构造边缘业务变化的模拟场景是合理推演，但文档没有证明本方案参数或 D 的效果。

### 5.1 改变机制结局，保留可观察线索

建议覆盖短 CPU 突发后释放、持续计算伴随工作集增长、后台写入积累后出现 I/O 压力、批处理结束后缓存/队列排空等响应机制。相似的当前负载，在不同历史趋势、释放节奏和任务组合下，应有不同的后续异常风险；所有标签继续由模拟器实际资源状态计算。

不能让全部模型可见输入完全相同却随机给相反结局，再只让 D 知道隐藏模式。可辨别线索必须来自预测前的遥测、历史或公开部署元数据；提供新特征时，相应固定基线也可用。先验证冻结表征能否保留这些线索；必要时为所有微调方法增加相同的轻量时序输入，而不是仅靠多加输出专家。

### 5.2 时间结构让出生、复用、回收各自有作用

| 阶段 | 建议设置 | 要验证的 D 能力 |
|---|---|---|
| 初次学习 | 几个模式各驻留足够长；示例 800～1600 区间，实际长度由开发可学性确定 | 新专家能学会，并保留有用旧专家 |
| 快速再现 | 多次回到旧模式；示例驻留 120～240 区间，顺序改变，间隔超过近期 replay 覆盖 | 复用是否比从近期混合数据继续调整更快 |
| 模式增加 | 逐步加入新业务响应律，数量事先未知；示例总计 6～8 种 | 按需扩展是否优于预先固定的小池 |
| 模式退出 | 插入短期任务，随后长时间不再出现；另保留周期复现的旧模式 | 区分值得保存的专家与应回收的冗余专家 |
| 安静期 | 业务减少、活动模式降低 | 活动专家减少是否真正省时省内存 |

这些是候选范围，不是已验证最优设置。先长后短对 D 有利且符合部署后业务轮换的可能情形；所有方法经历同一初次学习历史。若使用离线专家预训练，需单列为“有专家库的部署方案”，给固定方法对应的历史数据访问，并记录额外开销。

**休眠与删除必须分开定义。** 休眠保留权重以供再激活；删除永久回收专家及其状态，不允许在后面声称直接召回被删除的知识。专家冷存储若存在，也要计入存储和加载开销。

## 6. 可以采用有利条件，但结论应与比较条件一致

可以合理设定少量 replay、模式长期离开后复现、部署期间出现新业务、业务高峰期间更新预算更紧；也可以让 D 按需使用更多累计存储，而固定小模型保持部署时拓扑。场景无需让所有业务的正例率、事件数和幅度完全相同。

关键是同一测试流上各方法比较，并明确不对称来自哪种部署约束。例如，D 比固定四专家占用更多存储时胜出，首先支持的是“该动态部署方案优于固定四专家方案”；要把原因进一步归结为动态机制，需补固定大池与同规模路由对照。无需先证明固定模型永久无法收敛，部署期限内的优势本身可以成为结论。

D 不应凭审计用 regime 编号、已知阶段边界或未来标签触发生长/唤醒；这些只能用于离线诊断上界。固定方法也应有少量开发调参机会，否则主要测到的可能是超参数差异。

## 7. 建议比较与评估

保留原 A/B/C 命名，先从历史登记确认 B 的确切实现再纳入，避免在新协议中悄悄换义。023 第二轮现有完整在线结果仅 A/C。

核心对照为冻结 A、原固定 C、D，以及一个固定大专家池。固定大池应与 D 使用一致的稀疏路由/更新规则，防止把“dense 改 top-k”的收益当成动态扩展收益。D 内部至少比较禁用新增、禁用再激活、禁用回收三个版本；按阶段分配算力，先做最小 A/C/D pilot，再补全。

主指标建议预先选定“所有注册切换后前 W 区间的平均检测 AP”，例如 W=100，并同时报告全程 AP、最差模式、每次切换的配对差值。若论文主张提前预警，则把正确时间轴的 raw onset AP/事件召回设为主指标，并为全部方法对齐未来预测目标；不要用当前检测 AP 替代预警能力。窗口正例不足时按事先规则聚合多个切换，不在看到结果后挑窗口。

回收价值主要用实测专家驻留、总峰值内存、更新时间和 p95 推理时延评价，并检查性能损失；不要求删除本身必然提高 AP。对模型驱动真实迁移动作的结论，还需后续闭环测试；现有共同离线重放只证明相同输入轨迹上的预测表现。

开发上先固定小范围预算/学习率候选，避免把所有时间继续投入 C 容量门禁。可做相同旧流上的 1×/2×/4×更新诊断与小范围 lr 扫描，区分迟学和场景共性；预算与 lr 分开改变。正则消融是后续诊断，不预先认定是病因。

选择场景和配置后冻结，再使用未触碰的确认种子。旧 701～703 继续保留确认用途；新协议如需更多开发流，另登记开发种子。报告按流/事件块配对的不确定性，不能把相邻主机时间点当成大量独立重复。建议把 AP 增益 0.03 当候选实际意义阈值，并用确认结果判断是否达到，不能把开发胜出写成已经证明。

## 8. 下一步顺序与本次交付边界

1. 在新版本修复阶段 onset、漏结算及诊断口径，保存旧结果与新旧差异；扩充完整性检查的覆盖。
2. 用已有流做小规模优化诊断，确认固定模型表征与目标能学到什么；这是有限诊断，不再无限等待负梯度门禁。
3. 在新协议实现最小 D 与新的业务响应/时间安排，直接运行 A/C/D 开发 pilot。
4. 有差异后加入固定大池、D 消融和独立确认，分别解释新增、再激活、回收。

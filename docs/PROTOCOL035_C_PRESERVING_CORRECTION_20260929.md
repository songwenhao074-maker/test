## 1. 科学问题与范围

034 的证据是：D_live 相对原 D 六窗 AP 仅 +0.001090，后四窗 -0.002271；完整快照路由仍低于 C，且 Full 不优于 Fragment。按并列分数组重算，C/Full 路由六窗均值为 0.768296973/0.764832197；全程 AP 为 0.683632642/0.690050191，收益并未同时转化为回归优势。

现有缓存补查显示，U_first 保存的 5 份、V_first 保存的 8 份完整快照，在各自三次回归中均低于当前 C。U 前四份快照在创建后同阶段 128 步曾分别领先同期 C 约 0.00487、0.00732、0.00569、0.01083；后续落后不能仅归因于冻结快照参数被覆盖。初学与回归样本不同，也不能把这些差直接称为遗忘量。补充证据与数字均来自同一已观察开发轨迹，不是独立确认。

本轮只回答两个问题：
1. **能力覆盖**：历史快照是否在某些主机、时间段或当前可见风险区间具有相对 C 的局部优势？这些优势是否被总体均值掩盖？
2. **最小结构试验**：完整保留 C 的持续学习路径，只增加一个按主机输入产生修正量的分支，能否产生可测的额外能力，而不靠牺牲召回换取误报下降？

D_corr 是为 D 设计的**结构组件试验**，不是原 D 的同名完整升级版。本轮不实现动态新生、休眠、受保护专家库、复杂路由或硬删除。即使它成功，也只说明“独立共享学习＋输入条件化纠错”有开发价值，不能宣布动态记忆机制已验证。不要用旧 D 代码外壳包装新增单分支并声称验证了原生命周期。

能力诊断完成后，无论结果正负，都只运行下面已固定的一个纠错候选；诊断不得用来挑隐藏宽度、损失权重、路由器、种子或新情景。输入/工程/基线一致性失败才停止。这样避免无限诊断，也避免根据诊断结果临时挑算法。

## 4. A：历史专家能力覆盖诊断

## 6. C：唯一结构候选 D_corr

### 6.1 前向与初始化

共享主路径是 **整个、持续学习的 C_fixed5**。新增分支为 `Linear(73,32,bias=True) -> ReLU -> Linear(32,1,bias=True)`，恰好 2401 个可训练参数。float32 CPU；无 Dropout、额外归一化、AMP 或其他特征。

分支输入为时刻 t、主机 h 已发行的 z[t,h]。禁止加入主机ID、阶段/业务ID、时间、标签、未来切换点或整流统计。网络参数跨主机共享，输入不同可产生不同修正，因此它是输入条件化纠错，不是新增全局常数偏置。

独立 CPU RNG seed3501；隐藏层按该版本 torch Linear 默认 Kaiming-uniform/默认 bias 初始化，最后一层 weight/bias 全零。隔离随机数，不能影响 C 的初始化、采样或已有结果。

令 r=MLP(z)，修正 `delta=2*tanh(r/2)`，检测 logits 为：

```
l_D[0] = l_C[0] - delta/2
l_D[1] = l_C[1] + delta/2
```

再按原两类 softmax 得检测概率。固定尺度，不新增温度、阈值或门控超参。delta 为零或运行 D_off 时直接复制 C 输出以保证精确等价。D 的分类概率始终精确复制 C，本轮不宣称分类能力改进。

没有额外路由器，只有一个输入条件化修正分支；它学习输出接近零以避免不必要的修改。初始化的“不破坏 C”不等于训练后的“不会变差”，后者必须由保留原样的负结果与共同指标检验。

### 6.2 分支训练与时序

训练当前纠错分支的损失为，对抽样区间及所有16台主机取平均：

```
y_i = (raw_next_fault_i > 0)
m_C_i = issued_C_logit1_i - issued_C_logit0_i
L = mean(BCEWithLogits(m_C_i + delta_theta(issued_z_i), y_i)
         + 0.001 * delta_theta(issued_z_i)^2)
```

保持 C 原损失不变。纠错分支单独使用上述二元检测目标及固定弱修正惩罚，不复制 C 的分类辅助损失或 distillation。这是被明确登记的新组件目标，结果不能单独归因于网络拓扑而忽略目标变化。全部正常/异常主机行都进入损失，不按已知错例挑样、不增加 class weight、不改变负例分布。

独立 AdamW(lr1e-4, weight_decay1e-4, betas=(0.9,0.999), eps=1e-8)、clip_norm1。与对应 C 更新使用**完全相同的区间索引列表**，包括重复项；仍是每16预测步1梯度步、最近64成熟区间、最多32区间的原采样列表，不自行补抽。初期列表少于32时照用真实 C 列表。

时刻 t 严格按以下顺序：
1. 只暴露 tape 的当前观测 z[t]、C logits[t]，输出 D 预测并记录分支 hash。
2. 在本次预测之后发布 i=t-2 的标签，若 i>=0；写入最近64成熟区间缓冲。
3. 若 (t+1)%16==0，用该次 C 已记录批次更新分支一次。所有 i 都必须满足 i+2<=t。
4. checkpoint/日志写入，然后游标前进。

预测前可用标签只满足 i+2<t；这与预测后更新可用 i+2<=t 的顺序区别必须体现在审计中。流末游标5968、5969只结算最后标签用于计分，不再预测或梯度更新。

在历史成熟批次上允许用**当前分支**重新计算 delta，这是在线 replay；C margin 和 z 必须使用当时标签前已发行版本并 detach，不能用流尾 C 或后来更新过的 C 重算历史输入。分支梯度永远不能进入 C、底座、z 或其优化器。

推荐先独立运行 C，再用受游标限制的 tape reader 执行分支。磁盘含未来记录不构成读取许可；通过未来标签/未来 tape 扰动 fixture 验证先前输出不变。此优化等价于 C 与分支在同一部署流中按上述顺序运行，必须用短前缀 fixture 验证。不要把 tape 上分支训练的耗时当作 D 的全部部署成本。

### 6.3 记录与隔离

每次预测保存 delta、原 C logits、D logits/概率、分类概率、branch_version；每次更新保存成熟最大索引、批次、损失分项、梯度范数、参数 hash。记录修正量分位数、饱和率(abs(delta)>1.9)、正常/阳性行平均方向、参数是否真实更新。

每512个预测步及末尾保存分支权重、Adam状态、RNG、成熟缓冲/采样位置、游标、tape hash及预算状态。它们仅用于审计/精确恢复，**不是可供挑选的专家快照库**，不得根据性能选 checkpoint 或改变最终逐时刻预测。

若 delta 始终为零，先根据 fixture/梯度日志区分工程未更新与有效运行但没有学到增益。有效运行性能差是负结果，不是允许改参重跑的“工程失败”。

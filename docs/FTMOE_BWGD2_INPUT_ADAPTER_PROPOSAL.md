# 保留BWGD2、处理资源输入：近似训练分布的待审批方案

日期：2026-09-05。用户已明确异常分布只需大致相似，无需精确匹配。本方案尚未实施。

## 可行性与推荐方向

可以保留BWGD2的Bitbrain来源、VM筛选、任务到达与执行完成机制，在构造容器资源模型时增加独立的需求适配器，使模拟器运行的资源需求接近原014训练环境。与恢复整个OfflineTraceWorkloadV2相比，这条路线保留原生任务流，避免依赖来源不完整的version1/version2长数组。

适配必须发生在模拟器执行之前，调度器、容量可行性检查、实际执行、特征采集和物理标签都读取处理后的需求，不能仅修改导出的模型输入。处理CPU需求时还需同步处理max_ips及总工作量计算，保持执行模型自洽；实际完成时刻允许随负载和分配变化，不能一边改CPU需求一边强行维持原完成结果。

## 建议的首个固定配置

| 项目 | 建议 |
|---|---|
| 工作负载 | BWGD2派生适配器；原类和原入口保持不变 |
| 到达与选择 | 保留mean=1、sigma=1.5、原VM筛选；保留原到达数截断规则 |
| 正CPU需求 | 将原生base IPS限制到2–1860；0需求及完成状态保持0，不再把IPS乘18.6 |
| RAM需求 | 原生RAM需求×2.0 |
| I/O输入 | 每个存在的容器四项固定为1，空槽为0；明确这是训练一致的合成输入约定 |
| CPU/RAM/磁盘容量 | 恢复训练设置：3223.2 IPS；4295/8192 MB；8053 MB |
| 磁盘需求 | 见下文；单纯×1000只用于说明量级，无法满足三类异常目标 |
| 模型 | 原014权重与归一化先保持不变，四组共用相同输入 |
| 在线更新 | 原B/C/D预算、动态专家规则和延迟标签流程不变 |

首次检查采用简单、固定的映射，不为追求D高分搜索映射系数。若需要校准，只能在明确划分的开发采集流上依据资源统计和物理标签分布进行；校准阶段不读取模型预测、F1或D−B。

## 已完成的静态量级检查

对已保存的301小试动作前容器需求做数组变换，未重跑模拟器、未训练、未替换原轨迹。为便于比较，下表按全部槽位计均值，空槽为0。

| 需求 | 原离线训练均值 | CPU限幅、RAM×2、磁盘×1000后的均值 | 相对差异 |
|---|---:|---:|---:|
| CPU | 1144.28 | 1365.20 | +19.3% |
| RAM | 680.69 | 621.96 | −8.6% |
| 磁盘 | 1731.13 | 2126.04 | +22.8% |

转换后CPU上界与训练相同，RAM的95分位约2511，对应训练2913。这说明简单映射有希望达到用户要求的量级接近，但不说明新的异常比例、模型F1或主机聚合分布已经达标。真正运行后，拒绝部署、迁移、任务完成和占用都会改变，必须重新采集标签，不能用旧标签为修改后的需求计分。

只读检查还计算了RAM×2.2时的均值684.15；虽更接近训练均值，但当前建议先采用已有训练倍率2.0，不据单一均值增加调节项。该比较不构成模型参数搜索。

## 磁盘必须单独处理

BWGD2的DMBitbrain在整个任务期间返回constant_size；部署和迁移又要求当前需求不超过目标剩余容量。若磁盘容量固定、初始部署合法、各任务占用恒定，则新增/迁入不会造成磁盘过载，任务离开只会减少占用。因此只把1–3 MB放大1000倍或降低容量，主要改变部署拒绝，不能产生部署后磁盘增长型异常。

若希望异常仍大致呈现原训练的三类结构，建议加入一个明确登记的合成动态磁盘需求模型：

- 由旧训练数据估计磁盘占用的取值分布、零值比例和时间持续性，范围沿用0–9000 MB。
- 用独立、可恢复的随机状态生成有时间相关性的占用序列；不直接循环202步记录，不逐步独立打乱占用值。
- 序列按任务/VM身份绑定，与迁移落点无关；任务部署后可自然增长或回落，是否过载仍由实际需求与容量决定。
- 所有方法共享同一条生成轨迹。不得直接指定某个时刻的异常标签，也不得依据方法得分设置增长时刻。
- Bitbrain未提供磁盘空间占用，因此明确标注这是合成磁盘空间模型，不能称为实测占用或将读写吞吐直接当作空间。

若不希望增加任何合成磁盘模型，可以只做CPU/RAM异常对比；但这属于缩小资源覆盖范围，应事先说明，不能声称与原三类异常场景一致。

## “大致相似”的建议验收口径

原训练主容差标签异常比例为13.59%；异常内部CPU/RAM/磁盘约为84.43%/8.15%/7.42%。这些作为参照，不要求逐项复制。

建议开发小试以总体异常约5%–25%、CPU仍占主导、RAM和磁盘均出现实际过载为场景检查目标，并报告每类支持数。正常/异常各至少50的已有门槛继续使用；稀少类别不夸大统计结论。上述区间属于待审批建议，未替换原协议。

同时检查主机资源分位数、占用数量、事件持续时间、拟调度与实际落点差异，以及原归一化下的数值范围。容器均值接近不等于主机输入安全；尤其要复查第14台主机的退化训练分母。若再次出现病态归一化，提交共同输入兜底方案，不能通过禁止该主机部署或清零其真实负载规避。

## 分阶段执行建议

1. 审批需求适配器、训练容量、是否启用动态磁盘，以及上述近似分布目标。原015保持独立不覆盖。
2. 实现适配器并验证单位、CPU工作量、需求身份、保存恢复和标签因果性；磁盘模型仅依赖训练资源数据定参。
3. 在开发种子301采集300步加确认间隔，先做不读取模型分数的资源/标签分布验收。若不满足，报告偏差及有限的校准建议，不自动试大量压力组合。
4. 配置冻结后，才运行四组同源模型小试，依据原门槛决定是否进入后续开发和正式确认。

保留BWGD2不等于天然具备长期漂移：新任务仍可能从同一批VM轨迹开头读取。此次适配首先解决初始分布失配，不保证普通微调长期下降，也不额外注入时间漂移。

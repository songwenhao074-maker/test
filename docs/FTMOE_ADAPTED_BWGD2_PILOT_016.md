# 协议016：BWGD2需求适配小试结果与改进建议

日期：2026-09-05。结论：适配器已实施，完成300评分步及末尾确认间隔；场景分布未通过，按运行前登记边界停止在线微调。另完成冻结A诊断。B/C/D、学习率搜索和正式确认均未运行，不能据本次结果判断D是否优于普通微调。

## 实施与验证

新增独立AdaptedBWGD2及采集入口：正CPU需求限制到2–1860 IPS、RAM×2、四个I/O特征为1；CPU容量3223.2、RAM容量4295/8192、磁盘容量8053。到达、VM筛选、GOBI及执行检查沿用原逻辑。CPU最大供给及任务总工作量同步使用映射后的需求。

动态磁盘采用旧训练五块的逐容器需求估计经验一阶马尔可夫转移，取值0、1000、…、9000 MB；初始占用按训练经验分布抽取。转移统计不跨202步块边界；无模型分数、标签或开发数据参与定参。独立随机状态绑定回放种子及任务ID，重复读取同一时刻不会重复抽样，迁移不改变占用来源。它是合成磁盘模型，并未保留训练数据全部跨资源、跨任务关联。

3项专项测试通过，覆盖CPU工作量、排队重试不会重复放大、磁盘身份与读取一致性、随机状态恢复及转移统计边界。87个原采集/模拟器/调度相关Python文件哈希未变。原014回档基线、原015轨迹和原预测结果保持不变。

采集耗时70.95秒，进程RSS约0.60 GiB，既有资源限制保持。模型种子1，回放种子301，原014 epoch021 checkpoint，阈值0.5，原归一化。

## 原因分析

### 1. 平均需求接近，CPU状态分布仍差异很大

本次CPU/RAM/磁盘需求均值为1365.89/576.94/1783.33，训练约1144.28/680.69/1731.13。但训练CPU约38.52%低于186 IPS、61.48%处于1860上限，几乎只有低/高两种状态。本次低CPU比例仅1.71%，上限比例38.13%，其余多数为中间负载。

训练数据中的大量低需求任务可形成不同的初始聚集和后续负载上升。BWGD2任务较少进入这一低需求区，且CPU限幅压缩了原有高峰；仅对齐最大值和均值无法恢复这种时序关系。这是有代码和分布证据支持的解释，尚未通过下一轮控制实验分离其具体贡献。

动作前至少3个容器聚集在同一主机的比例，本次0.96%，训练9.98%；动作后本次1.08%。运行中活跃容器平均15.26个，已接近16的上限。因此单纯增加到达量不一定增加有效并发或恢复主机聚集，可能主要增加排队与拒绝。

### 2. RAM高需求尾部不足

训练RAM需求超过3000的比例为4.83%，本次仅1.54%；95分位从训练2912.52降至1610.61。RAM×2在旧轨迹静态计算得到的分布，并不等于经过新任务完成、拒绝与部署后的实际分布。简单倍率无法同时保证均值和高需求尾部接近。

### 3. 病态归一化仍存在，但不是全部原因

第14台主机归一化RAM和磁盘最大值约2.08×10¹¹、5×10¹¹。全程805次误报中125次位于该主机。统一兜底三个退化分母后仍有692次误报，说明需要处理该问题，但它不足以解释整个失配。

### 4. 拟调度和执行关系仍不同

482项拟迁移仅执行307项。按拟调度计算超容量、而实际原始标签正常的主机间隔有170个；全程805次模型误报中142次同时具有拟调度超载。拟调度差异有影响，但也不能解释全部误报。

以动作前真实主机需求判断超容量，原始标签F1=0.952381、容差F1=0.748899；以拟调度聚合判断，分别为0.470948、0.409326。说明当前物理状态仍有检测信号，而模型依赖的拟调度特征与结果关系不够匹配。

图分支的381次相邻槽位目标变化中249次涉及新/缺失任务身份，仍存在此前记录的图语义局限。本次未修改图结构，以免混入额外方法变更。

## 建议措施（未实施）

1. **共同归一化兜底。** 对原训练未覆盖或仅有CPU底值的列使用训练同类统计，四组相同；先验证旧参考集变化、输入范围与冻结推理。不能通过禁止第14台主机部署隐藏问题。单独修复预计不足以达标，本次诊断已说明其局限。
2. **将CPU校准重点从限幅改为状态和持续性。** 在明确的开发采集数据上，以旧训练需求为参照，设计固定的单调分段/经验分位数映射，匹配低负载与高负载占比及事件持续时间；仅看工作负载统计，不按模型F1调节。保持需求、max_ips和总工作量一致。映射会改变BWGD2原始幅值，应公开作为合成适配设置。
3. **单独检查RAM尾部。** 检查VM筛选是否偏向CPU型任务，以及RAM需求分位数和任务生命周期；先决定固定的尾部映射或代表性VM组成，不能简单把所有RAM再放大以追求异常数量。保留独立确认来源和全部失败结果。
4. **重新采集后，先验收主机聚合与物理异常。** 继续使用大致相似的场景目标，不要求精确复制类比例。若均值接近但主机占用、异常持续时间或归一化仍失配，先报告；通过后再开展四组在线更新。
5. **若上述共同输入处理后旧模型仍低分，考虑共同离线适配。** 这需要另行批准起始checkpoint变化；不应继续围绕D−B反复调模拟器。图身份/执行可行性输入改造同样属于独立共同变更，不能只施加于D。

本次不扩大种子、不改学习率、不启动动态专家比较。下一轮建议先批准“归一化兜底＋CPU状态/RAM尾部的无模型分数校准”，完成数据验收后再决定四组运行。

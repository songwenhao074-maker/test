## 仍存在的问题

1. **机制未识别。** D_corr 是完整 C 加 2,401 参数 MLP，独立 BCE 检测目标；C 原有复合损失不变。额外参数、额外优化与任务解耦同时改变，不能把收益全部归于结构，更不能归于记忆恢复。分类输出完全复制 C，没有分类提升证据。
2. **回归收益不等于抗遗忘。** U_first/V_first AP 仅 +0.000393/+0.000300，后期更好；这也可能是分支逐渐学会稳定校正。没有受保护记忆或恢复操作，不能把时间上的增长归因为恢复旧知识。W 的收益比六次回归更大，也提示一般检测校正值得优先检验。全程 AP 不是分块 AP 的线性平均，不能只靠分块权重解释全程差值。
3. **局部召回被 pooled 护栏掩盖。** V_rec3 AP +0.009818，但 recall 0.700787→0.679790（−2.10 个百分点，少检出 8 个正例）；该窗前 32 步 recall −3.37 个百分点，前 64 步 −3.03 个百分点。同期误报下降。这是阈值下的取舍，不能仅凭 AP 判定运行风险消失；不应事后改阈值遮盖它。
4. **单条已反复使用的轨迹，开发适配风险仍在。** replay seed=700、C seed=1、branch seed=3501。AP 小幅提升与 6/6 正向是值得继续的开发信号，尚无独立流证据。
5. **旧快照有局部可用信息，不等于完整记忆库有效。** 45 快照在 120 个支持充分的预定义 cell 中，76 个 cell 的事后最优 full 或 fragment 超过 C；cell 重叠，且对多个候选取最大有选择偏差。190 个预窗口合格配对中 full AP 高于 fragment 仅 2 个，平均 full−fragment 为 −0.003138；旧完整路由六窗仍比 C 低 0.003465。不能凭 76 个事后局部胜点启动大规模路由搜索，也不能断言不存在任何局部专家能力。
6. **新增资源没有同容量对照。** C 参考路径墙钟 58.12s、分支另 2.40s，D 部署需要两者，不能宣传 D 总共只需 2.40s。两进程离线计时不能直接等同生产部署延迟。校正范围实测约 [−0.613,0.416]，无接近 ±2 的饱和；没有证据优先放大 delta 上限。
7. **审计/恢复工程不完全。** implementation_manifest.execution_commit 记录 `2163838…`，这是 workflow 所在 main SHA，不是实际 checkout `a6bbca4…`；应分字段记录。runner 保存分支 checkpoint，但 CLI 没有恢复入口；C 正式 runner 没有每 512 步保存可继续的中间状态。synthetic resume fixture 并非真实命令行断点恢复验证。部分 audit 布尔值直接写死，需用实测证据支撑。本次连续完成且批次检查通过，不因这些工程缺口自动推翻预测结果，但不能宣称全部登记工程条件已得到验证。
8. **交接状态矛盾。** PROJECT_CONTEXT_LATEST 仍保留“034 最新、035 尚无结果”旧段，仅在末尾追加完成状态。下一轮需要整体重写当前状态；结果发布冲突应只重试发布，不能重跑训练。

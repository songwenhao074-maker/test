# Protocol 020：以离线未覆盖模式为主线的计划修订

日期：2026-09-09。状态：完成现有配置核查与计划修订；新场景尚未采集，模型未重训。本文件按用户最新要求，优先于此前“立即在旧 dev500/dev501 上执行 R2 调参”的安排。

## 1. 现有实验是否符合这个目标

**有不同 VM 样本和运行时漂移，但尚没有经过完整审计的“离线未见类型”设置。关键是实际在线起点已经经过 Protocol 019 和 020 S6 适配，不只是原始 v4。**

`artifacts/ftmoe_online/protocol_020/s6/adapted_v4_seed1/configuration.json` 明确记录：warm_start 为 019 适配模型，训练数据为 `protocol_020/adaptation_data/v1`。该 bundle 的 `train_indices=0..11`，分别为 baseline/cpu_fault/ram_fault/disk_fault，每类三个 episode。核对其 `episode_hashes[*].profile`，与在线 dev500 的主要配置如下：

| 模式 | S6 实际训练 episode 的 CPU/RAM/Disk 容量倍率 | dev500 对应阶段 | RAM 上限 |
|---|---|---|---|
| baseline | 1.00 / 1.00 / 0.90 | 相同 | 1400 |
| cpu_fault | 0.65 / 1.00 / 0.90 | 相同 | 1400 |
| ram_fault | 1.00 / 0.55 / 0.90 | 相同 | 2400 |
| disk_fault | 1.00 / 1.00 / 0.35 | 相同 | 未额外截断 |

dev500 的 cpu_recurrence 回到已有 CPU 配置；S6 的 12 个训练 episode 没有独立 recurrence episode，因此再现与连续阶段结构仍是值得评估的变化，但不等于新故障机制。dev501 标为 `stationary same-domain stream`，使用已有 baseline 配置。训练与在线的轨迹、阶段衔接和宿主状态并不完全相同，但这不能把重复使用的模式自动变成离线未见类型。

两条 R1 流实际使用 dev cohort，不是 vm_split 中单列的 online cohort。P20 的 S6 train 与这些 dev VM ID 分组不相交，只能支持这一层的来源隔离；不能外推到原始 v4、019 或选模数据的完整暴露范围。子 agent 的只读核查与主要配置重合结论一致，完整学习链审计仍为下一项。

证据入口：

- `artifacts/ftmoe_online/protocol_020/adaptation_data/v1/manifest.json` 的 `train_episodes`、`train_indices`、`episode_hashes`。
- 对应 `adaptation_data/raw/train/<profile>/seed401_steps400/manifest.json`，必要时再核对 seed402/403。
- `artifacts/ftmoe_online/protocol_020/drift_streams/dev_seed500_steps2000/manifest.json` 的 `phases`。
- 同目录 dev501 manifest 的 `name` 与 `phases`。

bundle 顶层 `profiles` 和 `adaptation/adaptation_profiles.json` 仍留有早期候选值，不能据此误判训练与在线配置不同。以实际 episode 配置、输入数组及其哈希为准。

因此，R1 的“没有稳定胜过 A”结论保留，但适用范围收窄为：**在这些已覆盖模式及其切换上，当前修正没有形成稳定优势。它没有充分回答模型能否在线学习离线未覆盖的新模式。**此前把主要模式未见性检查放在后面的 R5，不符合本次实验重点，需要调整顺序。

## 2. 重新定义“新类型”及证据范围

本轮主要研究：仍属于正常/CPU/RAM/Disk 标签，但工作负载的时间规律、资源间关系或环境组合在离线学习中没有覆盖。新样本、新 VM ID、新随机种子、不同异常比例、熟悉模式重新排序，分别报告，不能单独充当类型未见证据。

若要研究原来没有的 GPU、网络等新标签，应另立开放类别实验，增加输出头、标签协议和相应对照。现有三类诊断头不适合直接承担该结论。

“未见”相对实际起点的完整学习链核查：原始 v4、019 适配、020 S6，以及曾用于模型选择、归一化/物理映射拟合的数据。还要检查初始在线锚点与蒸馏教师；新模式在首次在线出现之前不能已经藏在初始化记忆里。新模式出现后，用其已成熟标签做在线学习或进入在线记忆是实验所需，不属于泄漏。

区分并分别登记两种证据：

1. **生成机制或参数组合未用于离线数据构造**：有明确生成规约、配置及排除清单支持。
2. **实际数据分布与离线覆盖存在差异**：比较需求/容量比、跨资源关系、时间滞后、持续时间、突发与事件结构，并检查重合与近邻范围。

生成配置不同不保证实际样本不同；统计分布不同也不自动证明是全新语义类型。历史训练链无法重建时标为“未见性未证实”，不能宣称绝对未见。当前仅完成上述 S6/在线主要 profile 重合核查，完整离线覆盖审计仍待执行。

## 3. 调整执行顺序

1. **先做新模式审计与场景注册**：从原 R5 提前，作为下一项实际任务。产出完整学习链覆盖表、候选模式排除证据及可观察性检查。
2. **先采集一个新模式的完整小试流**：数据层核验后运行冻结 A 与固定在线 C-residual，检验在线学习是否存在可重复的收益。保留当前结构与损失作为初始基线。
3. **再做 R2 损失/采样消融**：主要评价放在已核验的新模式开发流上，旧 dev500/dev501 作为熟悉模式保留与退化检查。暂停原先仅在旧两流上直接跑 8 组调参的安排。
4. 必要时实施 R3 的共同可观察特征与长期记忆；分别消融，不同时改变场景与方法后归因。
5. R0-B 动态部署缺陷解决后，进入 R4，对稳健的固定在线 C 和动态 D 做同信息、同损失、同记忆及成本对照。
6. 场景族扩展与独立确认沿用 R5/R6，但确认流不得参与选场景、选模型或调参。

本次仅修订计划。原始 v4、019 与 020 起点保持文件不变，不通过重新训练一个更弱的 A 来制造在线优势。

## 4. 新场景如何构造

候选先按以下两类审计；具体数值须在覆盖审计后登记，不能现在就声称它们已经未见或有效。

| 候选类型 | 具体变化 | 需要证明的内容 |
|---|---|---|
| 新工作负载时间模式 | 成组任务的持续突发、CPU 活动之后延迟出现 IO/RAM 压力；滞后应在实际输入历史可覆盖范围内 | 离线未用该生成规律；实际跨资源滞后/事件持续结构有差异；过去可见信息能帮助预测后续标签 |
| 新资源关系或环境组合 | 新任务混合比例和资源相关关系、需求与异构容量的联合变化；优先区分单因素和新组合 | 区分新组合与真正新机制，检查实际负载而非仅 profile 名称；不只是提高已有故障出现频率 |

主机、有效容量、任务到达和资源分布可调整，但物理超载标签与预测时点保持定义一致。禁止直接更换标签映射，或用本次执行结果、未来需求、phase ID、未成熟标签作为当步输入。

**陌生必须同时可学习**：新模式在一段时间内具有稳定规律，多次独立事件能提供反馈，输入含有预测线索。完全不可观察的随机标签变化、全机持续超载、所有故障仅一次出现，都不能用来证明在线方法应当占优。发现必要信息不在输入中时，先修正可观察性，并向待比较方法提供相同信息；新特征的收益与在线更新收益分开验证。

不能按“D 是否赢”筛选场景。按机制排除证据、实际差异、物理合理性、可观察性及事件支持选择；保留全部试探与失败记录。A 在某个确实新颖的场景上依然表现良好，属于离线泛化结果，不能因此删除该场景。

## 5. 运行时序与数据隔离

第一条候选流的开发起始时序登记为：熟悉模式 1000 步，新模式 2000 步，熟悉模式 1000 步，新模式重新出现 2000 步，熟悉模式 1000 步，共 7000 个评分步骤，另加 guard。这是待核验的开发预算，不是保证足够的门槛；数据审计若显示事件不足，先登记新的统一时长，再运行所有方法，不能看到某方法恢复慢后单独延长。

新模式再次出现时使用新的任务实例与轨迹片段，不重放完全相同的窗口，以检验学习保留而非记住样本。初次出现、熟悉模式返回、再次出现的状态连续传递，不能在每阶段重置 learner 或重新调参。phase 信息只作事后分析。

先只采集一类、一个开发种子核验工程与数据；通过后至少两类新模式、每类三个回放种子评估稳定性。不同种子若共享 VM 来源，只能算不同回放，不能当作独立来源。保持单进程顺序、3 GiB 可用内存保护。

预先区分离线数据、在线学习前缀、之后按时间到来的评分数据和最终确认来源。每一步都先预测，标签成熟后评分，再允许训练；后续曾用于评分的历史窗口可以进入在线训练，但不能回头修改其成绩。最终确认另留生成参数/事件实例及可用的独立来源，不是从开发失败样本中再次选出“测试集”。若完整离线链已经覆盖所有现有 VM 来源，应如实标注，只能先做生成机制隔离，或引入合法的新来源后再声称来源独立。

## 6. 对照要回答的问题

- **A vs 在线模型**：相同已冻结的离线起点、相同实际流、相同因果输入和标签延迟，检验成熟反馈是否改善后续预测。
- **更新关闭对照**：相同修正结构、零初始化但始终不更新；当前结构初始等价于 A，可验证等价后复用 A 的结果，不能重复计作独立证据。
- **保护开/关**：继续要求 learner、optimizer 和抽样完全配对，区分学到了什么与部署保护的作用。
- **B/C/D**：完整比较加入同起点的普通全参数在线 B、固定在线 C、动态在线 D。D 只有在 R0-B 通过、方法实现通过因果验收后才能作为有效主对照；额外参数与候选训练收益继续由 C-wide/C-budget 排除。

学习型方法之间共享信息与监督预算。输入、标签空间或额外特征改变后，要增加匹配对照，不能将信息优势全部称作动态专家优势。新场景只用于在线适应，不能先做同域离线适配，再把适配后的起点称作完全没见过它。

## 7. 成功判据与下一步交付

主结果分别报告熟悉段、新模式初见早期、新模式学习后的后续窗口、熟悉段返回、新模式再现；同时保留完整冷启动代价，不删除最初较差阶段。学习曲线按时间和已观察独立事件数展示，使用固定后续窗口计算 AP/F1、误报漏报、端到端诊断、恢复时间与成本，不只比较混合全流平均数。

在线方法需要在尚未用于训练的后续预测上体现改善，跨事件和回放可重复，且不以熟悉模式长期退化为代价。新颖性、A 存在不足、在线能够改善，是三个分别验证的命题；新颖性不保证 A 会输，更不保证动态 D 一定比固定在线 C 好。

下一项交付是 `offline_coverage_audit` 与 `unseen_regime_registry`：记录实际 checkpoint 链及数据用途、候选生成规约、离线排除证据、特征可观察性、物理标签、源/时间划分、固定时序、回放种子和开发/确认身份。审计通过后才创建新流。当前文件是计划，不能作为这两份审计已完成的证明。

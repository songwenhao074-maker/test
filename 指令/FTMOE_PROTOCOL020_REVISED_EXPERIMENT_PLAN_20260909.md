## 0. 目标、授权与文档优先级

最终目标：D 在持续运行、资源约束变化和故障模式再现时保持较高、稳定的检测与诊断能力，并相对 A/B/C 体现可重复的价值。不能只凭某个 F1 数字、一次专家新增或一条开发流宣布成功。

本计划落实用户此前授权：可以调整在线方法、主机设置、任务到达和资源分布；**不得重训或覆盖原始离线 v4**。制定计划时仅修改文档；用户随后要求继续，现已开始 R0 实施与验证，不直接扩大效果矩阵。

执行优先级：当前用户要求 > [离线未覆盖模式计划](FTMOE_PROTOCOL020_UNSEEN_REGIME_PLAN_20260909.md) > 本计划 > 最新 HANDOFF > 2026-09-08 复盘 > 原始详细方案。本文件保留方法与因果门禁规格；新模式审计和首条小试从 R5 提前到 R2 之前。原始方案的 S0–S6、旧门禁与失败过程保留历史价值；其重训 S6、直接推进 S8/S10、禁止开发期模型反馈调整场景等规定，不再作为本轮执行路线。

开发失败后应保存证据、诊断并继续处理有依据的问题；不能把失败改标 PASS。涉及标签泄漏、对照不公平或源文件变动时，先修正该问题，不能继续扩展无效实验。常规开发调整在既有授权内执行，不因历史停止条款重复索取许可。

## 2. 问题、证据与待验证假设

| 问题 | 当前证据 | 计划中的处理 |
|---|---|---|
| 主场景未隔离离线未覆盖模式 | S6 实际训练已含 dev500 使用的 baseline/CPU/RAM/Disk 主要容量与适配配置；dev501 为同域平稳流 | 先审计完整学习链并注册新负载时间规律或资源关系，完成新模式小试后再调 R2；旧流保留回归用途 |
| 学习目标失衡 | 提高学习率使误报增加；去掉约 8 倍检测权重提高 F1，但降低召回、PR-AUC | 分离采样、检测加权、分类、排序、蒸馏影响，见 R2 |
| 冻结参数不等于保住预测 | C/D 更新中间特征，后续固定分支仍接收变化的输入；P20 锚点出现退化 | 增加独立冻结基础预测，在线模块只修正最终分数，见 R1 |
| 容量输入未直接到达主要在线专家 | EAGate 位于容量图分支之前；已有容量投影开关默认关闭 | C/D 同时获得容量关系输入，隔离特征收益，见 R3 |
| 缺少运行中知识的长期记忆 | 近期窗口仅 128 步，锚点和蒸馏教师主要来自初始模型 | 增加新模式的长期情景记忆，见 R3 |
| 候选验证不是共同未见数据比较 | S8 先执行主模型更新再验证；一次出生的 70 个验证窗口中，16 个已用于当轮共享模型更新 | 先记录双方预测，标签成熟后比较，最后更新，见 R0 |
| 候选培养与触发样本脱节 | 缓存路由向量用于求中心，候选实际训练最新 10 个窗口 | 保存触发样本完整窗口、标签和错误类型，见 R4 |
| 触发统计本身会随学习变化 | 路由键、资源投影及前级 MoE 均更新；归一化熵 p95 约 0.996 | 用固定表征监测变化，结合持续错误；不要把高熵直接等同于缺专家，见 R4 |
| 启用和复用保护不足 | 仅短期综合损失准入；渐进权重到 1 时进入 Top-4 竞争；唤醒主要依据相似度 | 完整路径连续性、在线收益验证、反事实贡献与重新资格验证，见 R4 |
| 路由均衡和休眠规则方向冲突 | 一方面鼓励平均使用，一方面根据低使用率休眠 | 均衡约束做消融，休眠依据贡献和遗忘风险，见 R4 |
| 调度结果与拟放置不同 | 预测使用拟放置，标签来自实际执行及更新后的需求 | 分析可预测性与执行差异；结果只能作事后监督，见 R5 |
| 文档与指标口径陈旧 | 旧参考集、旧 lag/面积算法、顶层 profiles 与 episode 不一致 | 独立版本化、实际输入核验、分清训练锚点与保留探针，见 R0/R5 |

容量不足、梯度冲突和专家冗余仍是待检验假设，不得直接写成已证实原因。历史“候选通过”只表示通过旧准入规则，不再作为可靠外推收益证据。

## 3. 方法命名与公平对照

保留字母 A/B/C/D 的研究含义，增加版本后缀，防止替换实现后把不同方法的结果混在一起。

| 方法 | 定义 | 用途 |
|---|---|---|
| A | 现有冻结起点 | 基础能力参照 |
| B-legacy | 现有全模型在线微调 | 一般在线更新参照 |
| C-legacy | 现有固定普通 MoE＋EAGate 在线微调 | 复现与分析旧方案 |
| D-legacy | 当前 S8 实现 | 故障诊断和旧规则对照，不作为新机制已验证版本 |
| C-residual | 冻结基础预测＋固定数量在线修正专家 | 修订固定专家方案 |
| D-residual | 与 C-residual 相同结构与保护，加动态修正专家生命周期 | 主要候选方案 |
| C-wide | 从开始就配置较多固定修正专家 | 排除单纯参数增加的解释 |
| C-budget | 固定修正专家获得与 D 候选试训相当的在线训练预算 | 排除单纯多训练的解释 |

“4→5 专家”历史记录仅统计 EAGate，该模型还有另一组普通 MoE。新报告分别统计普通 MoE、EAGate、在线修正、影子和休眠专家，不以一个模糊总数代替。

C-residual 与 D-residual 必须共享：初始修正专家、特征、损失、记忆容量、保护规则、标签延迟、基础更新次数、归一化与随机种子配对。影子训练的额外开销单独登记，并由 C-budget 对照。C-wide 同时报告参数量与实际算力；不能声称它同时精确匹配参数和耗时。

## 4. R0：先修实验有效性与预测记录

**目的：在比较性能之前，确保每个“验证收益”确实来自当时尚未见过标签的预测。**

### 4.1 正确的时间顺序

对每个时间点 t：

1. 读取预测时刻可用的输入。用当时部署版本、冻结 A 和已存在的影子候选分别生成预测；记录输入窗口 ID、模型/拓扑版本、候选版本和原始分数。
2. 执行模拟器并观察当前结果。保持已登记的标签容忍策略；标签尚未成熟时不能进入监督、候选训练或准入判断。
3. 标签成熟后，用第 1 步保存的历史分数结算误差。禁止用已经更新过的模型重算这些分数，再称其为在线验证。
4. 更新资格验证统计、决定之后时间点使用的版本；随后才允许主模型和候选训练已成熟窗口。
5. 新创建的候选没有出生前的预测记录。其资格证据只能从出生后收集，不能追溯计算旧窗口“未来表现”。

重叠时间窗口共享历史输入并不自动构成泄漏，但标签因果约束必须逐项核验。标签延迟按实际任务定义登记；若未来部署无法获得此类标签，应另列监督可用性实验，不能继续假设本方案适用。

### 4.2 四种数据用途必须分开

- **训练锚点**：现有离线训练样本，可用于保持旧能力；成绩只能说明训练记忆保留情况。
- **在线短期/长期训练记忆**：仅收录已成熟窗口。任何未来加入训练的验证窗口，必须先完成当时预测的结算。
- **运行资格验证记录**：候选和部署版本真实在线预测形成的共同记录；用于启用、回退或再唤醒。使用它调规则的流属于开发数据。
- **独立保留探针**：不参与在线训练、路由或候选准入，仅作定期离线报告。若其结果被用于开发选择，就明确标记为开发评估，不能冒充最终独立测试。

### 4.3 R0 验收

- 修改未来标签/未来容量，不影响之前的预测、历史分数或准入决策。
- 资格验证结算发生在双方使用对应目标标签更新之前；记录审计中提前训练目标窗口数为零。
- 普通、影子、启用中、休眠和回退状态的保存/恢复均保留模型、优化器、样本使用计数、候选记录和随机状态。
- 旧结果保留但标注验证口径缺陷；修复后重新运行必要的 C/D 小试，不能把旧候选准入当作新规则的结果。
- 保留已修复 lag/面积实现；相同 raw/tolerance 标签分别报告。未来更换标签目标必须作为独立实验版本。

### 4.4 执行时明确的门禁依赖

为避免要求尚未实现的机制提前通过测试，将 R0 验收拆为两部分：

- **R0-A：共同因果基础**。包括预测缓存、标签成熟结算、无统计副作用、训练顺序审计、协议区分和已实现状态的恢复。该部分通过后，允许开展 R1 的固定修正工程与最小开发对照。
- **R0-B：动态部署完整性**。包括完整渐进路径、休眠/再唤醒资格与相关状态恢复；新建回退机制须在其实现阶段补齐测试。该部分未通过时，不得开展 D 的正式效果矩阵或将候选启用视为动态方法有效的证据。

2026-09-09 的合成测试已确认旧 gate 在 ramp 到 1 时不连续。因此先完成 R0-A，再推进不依赖动态拓扑的 R1 固定修正；R0-B 的失败必须在 R4 动态部署前解决，不通过延后阶段名规避门禁。R0 整体仍不能标记通过。

**R0-A 未通过时，只修复共同有效性问题；R0-B 未通过时，只允许已满足相应因果基础的固定方案开发，不扩展 D 效果矩阵。**

## 5. R1：验证冻结基础预测＋在线修正

### 5.1 目标结构

对检测和诊断分别使用：

`最终 logits = 冻结基础 logits + 修正强度 × 专家修正 logits 的加权和`

- 基础模型权重、buffer、归一化和推理模式冻结。在线训练不能经由共享可变参数改变基础输出。
- 修正模块读取冻结特征。输出修正头从零初始化，接入时严格复现 A。
- 防止“修正头和修正强度同时为零导致全部梯度为零”：训练中的影子修正通路必须保持可学习；零参与只作用于部署混合，或使用保证初始梯度有效的参数化。
- 修正强度依据已经结算的资格验证记录控制，不根据未来标签或场景 phase ID 控制。
- 始终保留最近已验证的部署版本。回退影响之后的预测，不可重写过去的失败输出，也不能宣称回退能完全避免延迟造成的损失。

### 5.2 最小对照

已在现有 dev500/dev501 固定场景完成 A、C-legacy、C-residual 对照。C-residual 未增加容量特征、未启用动态专家，沿用已有更新日程与共同损失。此结果只覆盖熟悉模式及其切换；下一项先审计完整离线覆盖并进行新模式小试，不能把这两条流当成已证明的离线未见类型。

新结构无法与旧结构完全匹配参数量时必须列出差异。对保留保护采用“启用/关闭”成对消融，避免把结构收益和保护规则收益混为一谈。

**进入下一阶段的依据**：基础路径不受训练影响；固定修正能够学习；资格规则可拒绝无益修正；既有能力与近期性能不再持续失衡。若不通过，分析修正梯度、特征与保护滞后，尚不新增专家。

## 6. R2：解开检测、诊断、排序与采样的影响

本阶段使用固定专家，不把专家数量作为变量。

前置条件：完成离线覆盖审计、新模式注册、数据核验与首条 A/C 小试。随后保持固定残差结构、输入、学习率、更新与曝光预算不变，在核验通过的新模式开发流上做 2×2 无保护组；具体运行清单随场景注册冻结。dev500/dev501 用作熟悉模式回归，暂停原先仅在旧两流上立即跑 8 组的安排。近期抽样异常比例与流比例的差异已在 R1 记录，不等同于已证明梯度失衡。后续保护配对须将准入评分与训练权重分开冻结，避免两个因素一起变化。分类/排序/蒸馏消融依次登记，不能把整套损失同时改掉后归因。

### 6.1 损失与采样对照

- 固定模型和数据，用“均匀/事件分层采样 × 检测正类权重 1/历史训练统计权重”构成 2×2 对照。固定 batch、更新次数及锚点预算，记录真实抽样正类比例和独立事件数。
- 不用加权后占比代替实测梯度。抽样检查各损失项梯度范数、方向冲突及主要更新模块；诊断只在需要定位时运行，不每一步全面计算。
- 在一个选定采样设置下，从检测监督开始，依次加入异常样本上的资源分类、联合排序，检查各项对检测与诊断的影响。不把整个损失同时改写后直接归因。
- 类别蒸馏默认只对具有有效诊断目标的异常锚点施加；将“正常样本也蒸馏类别”保留为单独对照。
- 原始教师存在错误时，不把其预测无条件当成正确目标。蒸馏约束保留行为与监督学习纠错的作用分别记录。

### 6.2 校准与评价

固定阈值 0.5 的历史指标继续保留。若引入阈值或概率校准，校准只能使用先前已成熟数据，并作为独立因素；各方法有相同可用标签和调节预算。PR-AUC 与阈值指标共同报告。

**选择依据**：兼顾误报、漏报、排序、资源诊断和保留能力。提高 F1 但持续损害召回与排序，不自动选为优胜方案；保留取舍表，不事后选择一个最有利指标。

## 7. R3：验证容量输入与长期情景记忆

### 7.1 容量关系

在固定修正结构上比较“原特征”和“原特征＋当前环境关系”：

- 当前实际放置下的需求、拟放置需求及各自需求/有效容量比；CPU/RAM/Disk 分开。
- 当前容量、过去窗口的容量变化与需求趋势、拟迁移和当前实际来源等因果可用信息。
- 拒绝率等执行统计只能取之前已观察时间点；当前实际执行结果、未来需求、raw_label 和 phase ID 禁止作为同一步预测输入。
- 新投影只在在线阶段学习；不改离线模型的图编码器或已有归一化。补充特征的尺度规则只用登记数据或过去观测确定。
- 相同容量特征随后也提供给 D，避免形成 D 独享信息的对照。

容量输入能改善固定专家，仍不能证明需要动态专家。

### 7.2 运行记忆

对照“近期＋初始锚点”和“近期＋初始锚点＋运行中长期记忆”。新记忆按已成熟的独立故障事件、资源模式与正常困难样本选取，防止一个持续事件占满缓存。

登记初始开发预算：每次更新仍为 32 个窗口；原组为近期 24＋锚点 8，新组为近期 16＋长期 8＋锚点 8；长期记忆起始为空时按登记规则回填近期。长期缓存先以 256 个窗口为开发预算，总存储与暴露次数分别报告。若改变预算，保存新配置而不覆盖旧结果。

长期记忆可以保存模型历史输出，但应关联当时版本和之后揭示的正确性；不能把未验证的错误预测持续固化为新教师。

**选择依据**：在故障模式离开近期窗口后再现时，保留能力确实改善；正常阶段没有付出持续过量误报代价。先做两个因素各自的对照，有必要时再做小型交叉对照。

## 8. R4：重新实现并验证动态专家的独立价值

以 R1–R3 选定且冻结的固定修正配置为 C-residual，复制出 D-residual。不得再同时改变输入、损失、保护和数据。

### 8.1 候选触发与培养

- 使用固定基础表征或单独冻结的监测器计算变化信号，避免把正在训练的路由器变化误认为环境变化。若必须更新监测器，其版本与重新校准应独立登记。
- 汇总已成熟的持续错误类型、资源条件、发生事件数，以及现有固定专家能否通过常规更新解决。异常率增加、高熵或一次大误差本身均不足以证明需要扩容。
- 候选记录保存完整窗口引用、已成熟标签、基线误差、错误类别、环境特征、创建时间与版本。不能仅保存向量中心，也不能用无关的最新窗口代替触发证据。
- 候选训练包含触发的困难事件、相关正常样本及必要保留样本。将“最新窗口训练”和“按错误证据训练”作为一次明确消融。
- 克隆父专家可以作为初始化；选择应同时参考相关样本上的已观察能力，不能把键向量相似度当成能力证明。

### 8.2 资格验证与启用

- 严格使用 R0 的历史预测结算。比较候选与当时部署版本、冻结基础及关闭该修正的反事实预测；反事实分数也必须在标签出现前记录。
- 资格判断检查连续多块证据、独立事件、误报/漏报及旧能力副作用；不能只采用一次平均综合损失下降。
- 验证块大小、所需事件数、误报预算和可容忍退化依据开发流及应用目标登记，进入确认阶段后冻结。证据不足应记录“未验证”，不当作“无效”或“通过”。
- 渐进启用的整个路径都需要验证，包括权重为 0、接近 1、等于 1，以及 Top-k 集合变化。消除因“年轻/成熟”状态切换造成的硬替换；不仅检查出生瞬间。
- 不能同时更换模型版本、路由规则和记忆策略后宣称仅是专家新增产生收益。

### 8.3 休眠、唤醒与优化器

- 使用已记录的有/无该专家预测差异估计贡献，兼顾稀有事件和不确定性；低频不自动等于无用。
- 对路由均衡损失做有/无消融。允许合理专业分工，不要求所有专家贡献相等。
- 唤醒先作为候选重新验证当前收益，再逐步参与；相似度只用于检索。
- 休眠保存权重、上下文摘要、历史贡献及优化器状态。再激活时保留或重置动量的策略预先固定并记录，不能静默丢失状态。
- 活跃、影子、休眠专家共同纳入总内存/参数上限；恢复时核对版本、ID 和参数身份。若仍逐个计算所有专家，再用掩码加权，应如实称加权路由，不能宣称已有稀疏计算收益。

### 8.4 动态对照

先比较 C-residual / D-residual，再加入 C-wide / C-budget。C-budget 获得不依赖未来事件的同等预算规则或共同上限；若事后按 D 实际开销配对补跑，应明确标为成本分析，不作为可部署在线策略。

**通过依据**：新专家在未见标签时的预测中体现可重复贡献，且不能主要由更多参数、更多更新或更好的输入解释。再现测试需要实际发生并记录“休眠、验证、同 ID 唤醒、有效复用”；单元测试或新增次数不替代该证据。

若 D 不优于稳健的 C，先定位触发、候选培养、路由干扰和有效使用时间；不默认把增加专家数作为修复。

## 9. R5：调整模拟器与数据场景，检查适用范围

**顺序更正：完整离线覆盖审计、未覆盖模式注册及第一条新模式小试已前置到 R2 之前。** 本阶段保留后续场景族扩展；不能等 D 完成后才核查它是否在学习新类型。新模式定义、初始 7000 步时序及验收以 [离线未覆盖模式计划](FTMOE_PROTOCOL020_UNSEEN_REGIME_PLAN_20260909.md) 为准，下面的 1000 步候选不覆盖该新安排。

### 9.1 场景族

保留旧 dev500/dev501 作为已使用开发回归集。新场景按因素建族，不只寻找一条 D 有利的流：

| 场景族 | 主要变化 | 用途 |
|---|---|---|
| 平稳正常＋少量故障 | 固定需求和配额机制 | 检查误报、无意义更新与误扩容 |
| 容量变化 | 固定需求生成规律，调整有效配额 | 隔离容量适应能力 |
| 需求变化 | 固定配额，改变到达率、资源关联、突发及持续时间 | 隔离任务分布变化 |
| 混合变化 | 配额与需求一起改变 | 模拟更复杂环境，明确混合漂移口径 |
| 再现与阶段顺序变化 | CPU/RAM/Disk 模式离开后返回，包含重复正常阶段 | 检查长期记忆及专家复用 |
| 渐变与突发 | 区分连续变化和突然切换 | 检查触发延迟及稳定性 |

旧 400 步阶段保留作为短阶段压力测试；长阶段起始候选为每阶段 1000 步，在模拟器资源检查后采集。1000 是开发起始设置，不是保证充分：必须报告检测、资格验证、启用和实际受益时间，确认不是专家出生时阶段已经结束。

主机异构、有效容量、任务到达、资源分布及持续时间均可调整。每次配置应列明改变因素和物理解释；数据门禁根据实际故障、独立事件、拒绝和活跃任务核验，不用相位名称代替证据。保持物理标签定义，不通过改标签制造方法优势。

### 9.2 数据来源和元数据

- 训练、开发、最终在线确认的底层 VM 来源不相交；仅换 replay seed 不能称来源独立。
- 先核查原 `online` cohort 是否曾用于开发。如果用过，不再称其为未见确认集；在允许数据范围内重新划分未参与选择的来源，或明确没有独立确认条件。
- 修正新数据生成器的 manifest：从实际 episode 配置生成元数据，并断言配置、输入数组与哈希一致。历史工件不原地改写。
- 所有方法使用同一份已冻结 replay；模型分数不反馈到同一条比较流的调度过程。若未来比较闭环调度，则建立单独实验，不与本轮固定回放混合。
- 模型反馈可以用于开发期场景探索，但必须保留失败场景并标记已参与选择。最终确认数据不得用于选配置、阈值、阶段长度或模型版本。

## 10. R6：独立确认、统计与最终判定

### 10.1 进入条件

R0 有效性通过；固定修正方案能学习并维持能力；动态机制在开发中有实际作用；模型、输入、损失、内存、生命周期规则、所有运行预算和场景生成规则已经冻结。

初次确认采用 3 条不同回放种子、独立于训练/开发来源的流，每条配对 3 个在线随机种子，核心方法 A/B/C-residual/D-residual。三个在线种子不等于三个不同离线模型，也不能把共享 VM 来源的回放称为三个独立来源。A 为确定性方法时可复用同一流的结果，但不能重复计为独立证据。

先只运行第一条确认流的成对组合核验工程正确性；不得根据其效果重新挑超参，再把该流继续当作未见确认。若因此修改方法，该流降为开发，重新登记剩余确认集合。额外算力/参数对照仅在主比较出现可重复优势时扩展。

### 10.2 指标与统计单位

- 检测：PR-AUC、误报率、漏报/召回、固定阈值 F1、概率校准；raw 与 tolerance 分开。
- 诊断：各资源支持数、召回、F1、混淆；明确“在真实异常上评估的分类能力”与“包含漏检的端到端诊断能力”不同。
- 稳定性：每阶段与最差阶段、独立保留探针、已学模式再现、回退次数、退化持续时间、滚动指标。
- 恢复：保留阶段内末段相对水平的描述性 lag，但不能仅凭它宣布 D 适应更快。另报告共同参考下的切换后预测损失/收益累计曲线；共同目标只能来自冻结开发定义或统一参照，不能分别给各方法降低目标。
- 动态机制：触发、创建、拒绝、启用、休眠、再验证、唤醒及有效使用时间，全部带版本与原因。
- 成本：推理和更新延迟、影子额外训练、峰值内存、总/可训练/活跃参数、实际专家前向次数。对冻结路径缓存仅允许缓存对应已知输入和版本，不缓存未来信息。
- 主要比较为同一流、同一在线种子的配对差异。host-step 和重叠窗口不是独立重复；按流及在线种子分层报告，避免把相同流上的多个种子或主机当成新的独立数据来源。
- 小样本区间仅作不确定性描述；不以大量相关窗口制造显著性。若跨流表现不一致，应列出适用条件和失败模式。

### 10.3 判定与失败处理

最终判定关注多场景下的整体能力、最差阶段、保留能力和成本。不能仅以 F1 上升而排序/召回持续恶化宣告成功，也不要求 D 在每一步、每一个指标上严格超过所有方法。

| 观察 | 处理 |
|---|---|
| C-residual 仍持续退化 | 返回 R1/R2/R3，检查保护、目标、特征及记忆，不扩大动态矩阵 |
| D 不触发 | 区分缺少扩容需求、监测盲区和证据不足；不人为强制出生来证明有效 |
| 候选被拒绝 | 核对完整触发样本、训练预算、梯度和候选能力；保留拒绝证据 |
| 启用后退化 | 核对共同未见验证、渐进全过程、路由干扰、记忆与保护；回退不删除失败成绩 |
| 启用太晚 | 同时报告短阶段限制和长阶段对照，不只延长到 D 获胜的长度 |
| D≈C-wide 或 C-budget | 收益优先解释为容量/预算；尚无充分动态机制独立价值 |
| D 只在部分场景有效 | 报告适用范围，继续有针对性开发；不选择性丢掉失败流 |
| D 多场景稳定优于控制组 | 扩大独立确认并保留资源成本，仍不声称必然泛化到所有负载 |
